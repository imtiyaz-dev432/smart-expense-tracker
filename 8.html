1 Income Model — 4 Fixes

Money precision, frozen timestamp, timezone, cascade.

#01 Float → Numeric(12,2)
Precision
Before
amount = db.Column(db.Float, nullable=False) # 0.1 + 0.2 = 0.30000000000000004
After
amount = db.Column(db.Numeric(12, 2), nullable=False) # Decimal — precise money handling
#02 Frozen timestamp — datetime.now call at import time
Crash / Data
Before
date = db.Column(db.DateTime, default=datetime.now(timezone.utc)) # Called once at import — same timestamp forever
After
date = db.Column(db.DateTime(timezone=True), default=lambda: datetime.now(timezone.utc)) # Called per insert — fresh timestamp ✅
Impact: Without lambda, all rows would have identical timestamps from module load time. "Latest first" ordering would be meaningless.
#03 DateTime timezone-naive → timezone=True
Data
Without timezone=True, timezone info was stripped on save — DB stored naive timestamps. Cross-timezone users would see incorrect times. Fixed by adding the flag.
#04 Cascade on wrong side
Dangerous
Before
user = db.relationship("User", back_populates="incomes", cascade="all, delete-orphan") # Income delete → User delete!
After
user = db.relationship("User", back_populates="incomes") # Cascade moved to User.incomes (parent side) ✅

§ Concepts Reinforced Yesterday

8 mental models tested and reinforced through real bug-fixing.

1 Final-state validation pattern (PATCH)

Validate the combined final state, not each field in isolation. If user sends {total: 3000, emi: 2000} to update {total: 500000, emi: 5000}, checking total <= emi field-by-field would reject valid input. Compute both new values → validate together → apply together.

2 Decimal serialization — every response needs float()

Numeric columns return Decimal objects. jsonify() can't serialize them. Every response containing a Decimal field must wrap with float(...). Same for datetime → .isoformat().

3 Decimal - float is illegal in Python 3

Mixing Decimal and float in arithmetic throws TypeError. Either convert both to Decimal (Decimal(str(value))) or both to float. For money, Decimal is safer — never introduce float.

4 Cascade direction: parent → child only

cascade="all, delete-orphan" belongs on the parent side (User.expenses). Placed on the child side, deleting a single row cascades to delete the entire parent.

5 Silent no-ops are the worst bugs

Validated input but forgot to assign to the model → response says "success": true while DB is unchanged. Client sees no error. Rarely caught by manual testing. Code review + tests catch this. Always double-check assignments after validation blocks.

6 SQLAlchemy session refresh after commit

After db.session.commit(), SQLAlchemy expires the object. Accessing a field re-fetches from DB, restoring Numeric → Decimal. So even if you assigned a float, the response field becomes Decimal again. Always wrap with float() in responses.

7 Callable defaults need a callable, not a value

default=datetime.now(...) freezes the timestamp at import time. default=lambda: datetime.now(...) makes it a callable — invoked per insert. Same pattern required for onupdate.

8 Enum-like values need alignment between route and model

Route validated 'active'|'pending', model CheckConstraint planned 'pending'|'partial'|'paid'|'overdue'. Mismatch → IntegrityError when constraint is added. Always define allowed values once (constants) and reference from both sides.
